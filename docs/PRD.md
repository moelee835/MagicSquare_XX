## 1. 배경

학습자는 OO 과제 맥락에서 **4×4 마방진**(1~16, 합 34, 빈 칸 2개)을 손·코드로 다룬다. Mom Test에서 **대각선 검산 누락** 후 **20분** 재작업이 확인되었다. 본 PRD는 **자동 풀이·UI 앱**이 아니라 **조기 판정(검증)** 에 범위를 둔다.

---

## 2. 목표

### 2.1 진짜 문제 (Problem Statement)

과제에서 빈 칸 2개를 채운 뒤 행·열·대각선 합을 맞췄다고 생각했지만 **대각선 하나를 검산에서 빠뜨려**, 틀린 상태로 **20분**을 쓴 뒤에야 잘못을 알게 되는 일이 반복된다.

### 2.2 제품 목표 (한 문장)

채운 4×4 격자에 대해 **10개 선**의 합이 **34**인지 **즉시 통과/실패**로 알려, 잘못된 “맞췄다” 판정을 **재작업 20분 전**에 차단한다.

### 2.3 비목표 (Out of Scope — v0.1)

- 4×4 **자동 채우기·솔버**
- **PyQt/GUI** 격자 편집기
- **TDD/Cursor** 등 도구명을 요구사항에 넣는 것 (프로세스는 별도)
- 빈 칸 **위치 추천·힌트**
- ECB **전 클래스** 일괄 구현

## 4. 도메인 요구사항

### 4.1 격자 (Input)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| D1 | 4×4 정수 배열 | P0 |
| D2 | 빈 칸은 `0`, **정확히 2칸** (시나리오 문서화) | P0 |
| D3 | 채워진 칸은 **1~16**, **중복 없음** | P0 |
| D4 | 목표 합 **34** (4×4 표준 마방진) | P0 |

### 4.2 10선 (검증 대상)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| L1 | **행 4개** 각각 합 = 34 | P0 |
| L2 | **열 4개** 각각 합 = 34 | P0 |
| L3 | **대각선 2개**(↘, ↙) 각각 합 = 34 | P0 |
| L4 | 실패 시 **어느 선**인지 식별 가능 | P0 |

## 5. 기능 요구사항 (v0.1)

### 5.1 검증 (Core)

| ID | 요구사항 | Mom Test 연결 |
|----|----------|----------------|
| F1 | 주어진 격자에 대해 10선 합 검사 | S2 — 대각선 포함 |
| F2 | 합 ≠ 34인 선 목록 반환 | 조기 판정 |
| F3 | 1~16 중복·범위 위반 검사 | 실패 인식 조건 |
| F4 | OO 과제와 동일 조건 **픽스처**로 동작 재현 | S1 — “지난주 OO 과제” |
| F5 | 대각선만 틀린 격자 → **실패** (통과 금지) | S2 — “대각선 빼먹음” |
| F6 | 정답 격자(슬라이드/과제 예시) → **통과** | Green 시나리오 |

### 5.2 인터페이스 (Command)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| C1 | CLI 또는 `pytest` **단일 진입점**으로 F1~F6 실행 | P0 |
| C2 | GUI 없이 파일·배열 인자로 검증 가능 | P0 |

### 5.3 Test Loop

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| T1 | **Red:** 대각선-only-fail 테스트 존재 | P0 |
| T2 | **Green:** 정답 픽스처 통과 | P0 |
| T3 | 잘못된 입력 → **수 분 내** 로컬 피드백 (CI/수동 20분 재작업 전) | P1 — S3 |

## 9. 표면 문제 (금지 — 요구사항으로 올리지 않음)

다음은 **기능 요구가 아님** (Mom Test 표면 문제 보관):

- “검증·채우기 **프로그램**을 만든다”
- “**솔버 앱**이 필요하다”
- “**Validator/Solver 클래스**만 있으면 해결”

v0.1은 위를 **직접 구현 목표로 삼지 않고**, **10선 검증·테스트**로 진짜 문제만 다룬다.
